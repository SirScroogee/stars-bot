# Project: Telegram Stars & Premium Bot — ТЗ

## 1. Краткая цель
Создать публичный Telegram-бот (aiogram) для автоматической продажи Telegram Stars и Telegram Premium с внутренними балансами, оплатой через сторонние провайдеры (TON/USDT и др.), управлением через админ-панель и полной учётностью прибылей/возвратов/рефералок. Основная бизнес-модель — маржа от продажи.

## 2. Ключевые требования
- Язык: Python 3.10+, фреймворк: aiogram (3.x).  
- БД: PostgreSQL (реализуем через SQLAlchemy async + Alembic).  
- Контейнеризация: Docker / docker-compose.  
- Безопасность: не хранить секреты в репозитории, валидация вебхуков, подписи, rate-limit.  
- Архитектура: модульная (bot → services → db → payments).

## 3. Пользовательские роли
- Пользователь — покупает Stars / Premium, управляет балансом, использует чеки и промокоды.  
- Администратор — управляет товарами, тарифами, промокодами, просматривает логи и статистику.  
- Сервисы/боты — внешние провайдеры платежей / fragment API.

## 4. Основной функционал
1. Каталог товаров (Stars, Premium — 3/6/12 мес.). 
2. Покупка: выбор получателя → выбор количества → способ оплаты (balance / USDT / TON /) → выставление счёта → подтверждение/обработка.
3. Внутренний учёт: users (tg_id), balance_ledger, orders, payments, transactions, checks, promo_codes, referral_earnings. Полная журнальная история операций.
4. Отложенная выдача: покупка зачисляется на внутренний баланс; выдача в Telegram через fragment API происходит только по явной операции "получить/отправить".
5. Чеки (создание/активация), промокоды, реферальная система (до 3 уровней, настраивается).
6. Inline-режим (калькулятор / быстрые покупки).

## 5. Нефункциональные требования
- Атомарные транзакции при изменении балансов (update users + insert balance_ledger).
- Idempotency для создания заказов (order_key).
- Логирование/аудит (audit_logs), retention 180 дней (архивация).  
- Тесты: unit тесты для критичных сценариев (idempotency, race conditions, webhook flow).

## 6. Интеграции
- fragment API (официальный) — для выдачи Stars / Premium.
- Платёжные провайдеры (TON / USDT / cards) — webhooks и API (будут добавлены MCP для каждой платёжки позже).

## 7. Регламент операций (кратко)
- Создание заказа → orders (status=pending) → worker/queue обрабатывает → при success: transactions + balance_ledger + users update → audit_logs → уведомление пользователю.
